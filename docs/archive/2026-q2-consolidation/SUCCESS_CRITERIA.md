# Success Criteria

## 1. Overview

Karsa's economic and intelligence claims rely on rigid, measurable definitions of "Success" at every layer of the workflow hierarchy. A failure at any lower level propagates upward, potentially invalidating the entire operation.

## 2. Hierarchical Definitions

### 2.1. Execution Level
A single request/response cycle to the LLM.
- **Measurable Conditions**: 
  - The LLM returns a valid HTTP 200 response within the timeout threshold.
  - The response strictly adheres to the requested output format (e.g., raw JSON, valid Markdown, or unified diff).
- **Required Evidence**: `metadata.json` showing `status: SUCCESS` and `duration_ms` > 0.
- **Acceptance Rules**: If an execution returns raw text when JSON was requested, the Execution Level has FAILED.

### 2.2. Agent Level
A specific persona (e.g., Coder) completing its assigned task within a cycle.
- **Measurable Conditions**: 
  - The agent produced the required artifact (e.g., `feature.py`).
  - The output resolves the specific prompt instructions without violating constraints.
- **Required Evidence**: An artifact diff generated by the agent.
- **Acceptance Rules**: If the agent writes code but removes pre-existing functionality without permission, the Agent Level has FAILED.

### 2.3. Review Cycle Level
A single loop of `REVIEW` -> `REVISE`.
- **Measurable Conditions**: 
  - The number of open blocking issues decreases from cycle `N` to cycle `N+1`.
  - The revision successfully applies without triggering a `PatchApplyFailed`.
- **Required Evidence**: A positive `convergence_score` in the `ReviewMetricsTracker`.
- **Acceptance Rules**: If a review cycle introduces more bugs than it fixes, the cycle has FAILED (divergence).

### 2.4. Workflow Level
The end-to-end process from `IDEA` to `APPROVED`.
- **Measurable Conditions**:
  - The `APPROVED` state is reached.
  - The total `cost` is strictly less than `max_workflow_cost_usd`.
  - The total iterations are strictly less than `max_review_cycles`.
- **Required Evidence**: `workflow_metrics.json` showing the final state and cost.
- **Acceptance Rules**: If the workflow reaches `APPROVED` but cost $2.00 against a $1.00 budget (due to a Governance Engine failure), the Workflow is retroactively classified as FAILED.

### 2.5. Repository Change Level
The final impact on the external target repository (e.g., `stock-bot`).
- **Measurable Conditions**:
  - 100% of the repository's native unit tests pass.
  - The linter returns 0 new violations.
  - A clean Pull Request is generated.
- **Required Evidence**: CI/CD sandbox exit code `0`.
- **Acceptance Rules**: If the code works but introduces a new security vulnerability (SonarQube Blocker), the Repository Change has FAILED.
