# ADR-044: Capital Allocation, Evidence Weighting, and Risk Budgeting Model

## Status
Frozen

## Date
2026-06-14

## Context
Designing a capital allocation model for the Virtual Investment Firm (VIF) that scales to 100M+ evaluations per day and avoids survivorship bias requires a robust, math-calibrated model. We must address:
1. **Survivorship Bias**: Successful workers tend to capture all capital, permanently starving new or recovering workers of sample size.
2. **Hindsight and Over-Confidence Bias**: Raw agent confidence is often miscalibrated. Allocators must discount confidence using realized prediction history.
3. **Beta Luck vs. Alpha Skill**: Allocators must distinguish between returns generated by macro regime factors (beta) and returns generated by thesis skill (alpha).
4. **Aggregate Inflation**: Modeling every adjustment or input parameter as separate database entities leads to write contention and performance bottlenecks.
5. **Risk Budgeting**: Capital limits are insufficient without proper propagation of volatility, drawdown, and exposure budgets down the asset-class hierarchy.
6. **Governance Severity**: A binary (on/off) governance response leads to crude, high-risk portfolio liquidation events when minor warnings would suffice.
7. **CIO Availability**: Under standard flows, adjustments require both Governance validation and CIO signatures. System availability requires a clear fallback policy if the CIO agent is offline.
8. **Attribution Recalculation**: Late evidence updates will trigger attribution recalculations, risking historical drift and replay non-determinism unless correctly isolated.

## Decision
We implement the following capital allocation, evidence weighting, and risk budgeting model:

1. **Evidence Weighting & Attribution Dependency**:
   - Return scores from the Performance Engine are multiplied by causal factor weights from the Attribution Engine: `Calibrated Return = Realized Return * Attribution Factor`.
   - This scales allocation strictly to true alpha contribution, ignoring lucky gains from beta.

2. **Survivorship Bias Mitigation**:
   - **Exploration Floor**: The engine guarantees that a minimum of $5\%$ and maximum of $20\%$ (default $8\%$) of total virtual capital is reserved for new or probation workers.
   - **Diversification Cap**: Maximum allocation is capped at $25\%$ per worker or strategy, preventing capital concentration.
   - **Probation Funding**: Recovering or new targets are funded with probation limits until slippage and returns stabilize.

3. **Confidence Calibration**:
   - Raw agent confidence is calibrated against historical prediction error (Brier score): `Calibrated Confidence = Raw Confidence * (1.0 - Brier Score)`.

4. **Regime Partitioning**:
   - Allocation policies contain parameters partitioned by active regime (`regime_id`), allowing the model to optimize weights specifically for bull, bear, or sideways regimes.

5. **Zero Mutable Aggregates / Single Policy Ledger and Write-Once Ledger Records**:
   - The context contains zero mutable aggregate roots, avoiding lock contention and OCC overhead entirely.
   - Both `AllocationPolicy` and `AllocationRecord` are modeled as strictly write-once ledger entries. Policy updates append a new version row, and calculation inputs/recommendations append an allocation record, offloading large context payloads to object storage (Object Lock) for scalability and determinism.

6. **Allocation Target Hierarchy & Portfolio Risk Budgets**:
   - To eliminate worker-centric migration risks, the engine targets a polymorphous hierarchy (`PORTFOLIO -> STRATEGY -> THESIS_VERSION -> WORKER`) using a unified `AllocationTarget` value object. Downstream execution engines enforce active limits recursively.
   - We allocate both **Capital** limits and **Risk Budgets** (Volatility, Drawdown Budgets, and Exposure Limits). The sum of child risk budgets is constrained recursively by covariance-adjusted ceilings:
     $$\sigma_p = \sqrt{w^T \Sigma w} \le \text{Portfolio Risk Budget}$$

7. **Eligibility Gating Layers (Hard Gates vs. Soft Multipliers)**:
   - Calculations use a two-pass evaluation:
     - **Pass 1: Eligibility Evaluation**: Validates hard gates (Governance Breach, Severe Review Failure [Score < 0.30], Extreme Calibration Failure [Brier > 0.80]). Triggering any gate sets eligibility to `0.0` immediately.
     - **Pass 2: Allocation Scoring**: Applies soft multipliers to eligible targets:
       $$\text{Adjusted Return} = \text{Realized Return} \times \text{Attribution Factor} \times (1.0 - \text{Brier Score})$$
       $$\text{Final Weight} = \text{Adjusted Return} \times \text{Review Multiplier} \times \text{Governance Multiplier} \times \text{Post-Mortem Multiplier}$$

8. **Governance Severity Model**:
   - Compliance overrides support three levels:
     - **WARNING**: Logged only; zero capital/execution impact.
     - **SOFT_LIMIT**: Scales maximum policy allocations and active limits down to 50%.
     - **HARD_STOP**: Defunds the target immediately (Eligibility = 0.0) and triggers execution liquidation.

9. **CIO Offline Policy**:
   - If the CIO Agent is offline/unavailable, the system executes **Option B (Continue Last Approved Policy)**. Active weights and policies remain unchanged, but Governance `HARD_STOP` and `SOFT_LIMIT` overrides bypass the CIO to defund or throttle targets immediately.

10. **Attribution Recalculation Policy**:
    - Recalculating historic attribution factors NEVER mutates historical `AllocationRecord` entries (preserving replay determinism).
    - If the recalculated variance of active attribution factors exceeds 10%, the target is flagged as a **Reallocation Candidate**, triggering a new run to adjust future allocations.

11. **Exploration Floor Bounds (5%-20%) Ownership**:
    - **Governance Engine**: Defines the absolute floor bounds (5%-20%).
    - **Capital Allocation Engine**: Calculates the exact ratio distribution (default 8%).
    - **CIO Agent**: Approves modifications to the active floor percentage.
    - **Review Engine**: Audits floor compliance.

## Consequences
- **Fair Worker Funding**: Exploration floors ensure new workers can accumulate the necessary sample size.
- **Accurate Alpha Scaling**: Attribution integration rewards actual skill rather than market luck.
- **Audit Determinism**: All allocation parameters and input factors are permanently frozen in object storage.
- **Hierarchical Risk Control**: Volatility is managed natively across portfolios, strategies, and workers.
